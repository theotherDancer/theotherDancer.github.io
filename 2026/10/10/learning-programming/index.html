我的编程学习之路

从这里开始记录我的编程学习之路。

现在：主攻 Java，C 语言先按下暂停

一开始我是从 C 语言入门的，它帮我理解了变量、循环、函数、内存这些底层概念。最近我把重心转到了 Java——不是 C 不好，而是想在「面向对象 + 工程实践」这条路上先走一段。C 暂时按下暂停，等需要时再回来补。

学习路线（大致走了一遍）

  1. 基础语法：变量 / 运算符 / 分支 / 方法 / 数组
  2. 面向对象：封装、构造方法、final、枚举 → 继承（extends / 重写 / super）→ 多态（instanceof / 强制类型转换）→ 抽象类 / 接口 / 内部类
  3. 常用 API：String、StringBuilder、ArrayList，以及 System / Object / 包装类（BigInteger、BigDecimal）
  4. 综合练习：一个控制台「文字格斗游戏」的登录 / 注册模块，把学过的串起来
  5. 算法：二分查找、分块查找，冒泡 / 选择 / 插入 / 快速排序，以及递归

最近踩的坑（都是真金白银换来的）

1. find() 是「消费式」的
正则里 while (m.find()) 才是正确写法；循环前千万别多调一次 find()，否则第一个匹配会被悄悄吞掉。想「匹配但不消耗」，用前瞻 (?=...)。

2. 报错位置会骗人
写分块查找时，类的大括号提前闭合，方法掉到了类外面；JDK 25 把它当成「紧凑源文件」解析，结果报错指向第 1 行（”压缩源文件不应有程序包声明”），和真实原因八竿子打不着。教训：报错位置离谱时，先数括号。

3. 边界 bug 最阴险
查 48 总是提示「没有你要查找的元素」，因为循环写的是 i < endIndex，漏掉了块的最后一位；改成 <= 才对。而查 50 却正常——因为 50 恰好不在边界上。这种「时灵时不灵」的错最难查。

4. 递归先写出口
出口要在第一行、条件用 i >= j（把「空区间」和「单元素」都挡住）。出口忘了写或位置不对，就是 StackOverflowError 或数组越界。

5. 溢出是静默的
int 装不下 13! 以上的阶乘。gatFactorial(20) 打印出来是 -2102132736——Java 只保留结果低 32 位，再按补码读。数值计算前先问一句：「这个类型装得下吗？」

调试方法论（这段最值钱）

  1. 改一处、马上重跑：错误是层层揭开的，一次改三处就分不清是谁的锅。
  2. 用标准答案对照：拿 Arrays.sort、Python 的 math.factorial 当参照物，比肉眼看快得多。
  3. 先看异常栈：某一行重复几百次 = 无限递归；指向 arr[i] 的那行 = 真正越界的地方。
  4. 边界用例：空数组、单元素、两个元素、全相同、已有序、完全倒序。

心得

  • 基础要懂，但不必死背；重点是读代码、调试和判断的能力。
  • AI 可以帮我写初稿，但理解每一行为什么这么写，才是真正学到手的部分。
  • 面向对象不是背概念，而是用 private / getter / setter 把「能改」和「不能改」区分开。

更快一点吧，再快点。
